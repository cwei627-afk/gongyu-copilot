# 关键架构决策记录

本文件持续记录影响系统职责、数据权威、证据使用与技术边界的决策。以下初始决策来自用户于 2026-09-28 明确给出的项目要求，状态为「已接受」，不表示功能已经实现。

后续按编号追加，写明背景、决策及影响；待讨论内容标为「待定」。已接受决策发生变更时，保留原记录并标记被哪条决策替代，不静默覆盖历史。

## ADR-001：业务系统持有业务事实

- **日期 / 状态：** 2026-09-28 / 已接受
- **背景：** 生产数据和炉次号动态产生，AI 层不能成为另一份生产事实来源。
- **决策：** MES/ERP/WMS 是业务事实的 Source of Truth；真实环境通过 API、数据库视图或其他正式接口查询。PoC 使用 SQLite 模拟三个系统后端，AI 不维护完整生产数据副本，不预生成全部合法炉次号；炉次存在性以 MES 为准。
- **影响：** AI 层承担交互与编排职责；模拟数据源与真实系统保持相同的权威边界。

## ADR-002：正式规则与 Evidence First 约束结论

- **日期 / 状态：** 2026-09-28 / 已接受
- **背景：** 语义相似或模型已有知识不能证明某项生产处置符合企业要求。
- **决策：** 企业正式 SOP、操作规程、质量标准是业务规则的 Source of Truth。工艺判断使用当前炉次真实数据和对应有效规则；LLM 不自定正常范围。RAG 正文必须直接支持答案，证据不足时拒绝生成确定性的生产处置结论。
- **影响：** 答案尽可能携带 `document_name`、`version`、`chapter`、`section`、`page`，不编造缺失出处。

## ADR-003：严格区分三类异常

- **日期 / 状态：** 2026-09-28 / 已接受
- **背景：** 接口故障、数据缺失和工艺违规的含义不同。
- **决策：** timeout、500、鉴权失败属于系统异常；炉次不存在、关键字段为空、数据过期属于数据异常；真实参数违反对应当前有效规则才属于业务/工艺异常。
- **影响：** 不把系统失败或 MES 查不到炉次解释为工艺异常；错误码和响应结构留待明确的接口设计任务决定。

## ADR-004：生产处置保留人工决策

- **日期 / 状态：** 2026-09-28 / 已接受
- **背景：** 项目定位为生产知识与异常辅助分析 Copilot。
- **决策：** AI 不直接向 PLC、控制系统或生产设备发送控制指令。生产处置建议必须保留 Human-in-the-loop，由人工复核与决策。
- **影响：** 项目输出辅助分析与建议，不执行设备控制。

## ADR-005：采用限定技术栈，按明确任务推进

- **日期 / 状态：** 2026-09-28 / 已接受
- **背景：** 这是教学型制造业 AI 集成 PoC，需要结构清晰、代码易懂，避免过度工程化。
- **决策：** 使用 Python、FastAPI、用于模拟业务系统后端的 SQLite；后续由 Dify 承担 RAG、Agent、Workflow、Tool Calling，后期加入 Docker / Docker Compose。第一阶段不引入 React、LangGraph、知识图谱、多 Agent、Kafka、Redis、Kubernetes 或复杂微服务。每次只完成用户明确要求的任务。
- **影响：** 本轮仅创建三个工程文档；业务功能、接口实现及部署配置均不在本轮范围内。

## ADR-006：任务包 01 的 Mock 后端与查询约定

- **日期 / 状态：** 2026-09-28 / 已接受（任务包 01 范围内的实现选择）
- **背景：** 用户明确授权五个 Mock 查询接口、Pydantic Schema、小型数据集及基础 API 测试；ADR-005 中“本轮仅文档”是上一轮范围，现按新任务推进，其技术边界继续有效。
- **决策：** 一个 FastAPI 应用按 MES/ERP/WMS 划分路由，分别使用三个 SQLite 文件模拟后端。直接使用标准库 sqlite3，不引入 ORM。显式初始化样例，已有数据库不覆盖；查询使用只读连接和参数绑定，动态 ID 以实际查询结果为准。
- **响应：** 对象不存在为 404 数据异常；必要字段缺失、记录缺失或格式无效为 409 数据异常；数据库查询失败为 503 系统异常。错误与成功响应均有 Pydantic Schema。
- **数据粒度：** 每炉一条温度及一条成分记录，每物料一条汇总库存；合成数据仅用于接口演示，不是工艺标准。返回采集/更新时间，本轮未给出过期规则，不自行设定有效期或正常范围。
- **验证：** 标准库 unittest + FastAPI TestClient，HTTPX 仅作测试依赖；临时数据库隔离每个测试。
- **影响：** 五个接口只返回事实与明确的数据/系统错误；不接入 Dify、RAG、LLM、Docker，不判断工艺异常或输出处置建议。

## ADR-007：统一 API 失败语义

- **日期 / 状态：** 2026-09-28 / 已接受（本轮失败语义任务）
- **背景：** 调用方需明确区分事实不存在、数据不可用、参数错误及系统失败，不能把查询失败解释成工艺异常。
- **决策：** 保留原数据错误码，扩展统一结构的 request/system 错误：422 参数非法、502 模拟上游失败、504 超时、500 内部故障；数据库错误仍为 503。未知路由使用 request / ROUTE_NOT_FOUND，与 data / OBJECT_NOT_FOUND 区分。详见 [API_CONTRACT.md](API_CONTRACT.md)。
- **校验：** ID 仅验证 1–128 字符且无空白/控制字符，不枚举合法炉次号；数值必须有限，不设工艺范围。NaN/无穷值视为数据不可用。
- **验证：** 按本轮明确要求加入 pytest 测试依赖，保留原回归测试；在后端访问边界注入故障，模拟上游 500 和 timeout，不新增业务端点、对外故障开关或 LLM。
- **影响：** 所有系统失败均表示事实状态未知；成功及原数据错误结构保持不变，仅增加 request 类别及相关错误码。ADR-006 的测试方式由本条扩展。

## ADR-009：RAG 资产与 Evidence First 离线校验

- **日期 / 状态：** 2026-09-28 / 已接受（任务包 05 范围内实现选择）
- **背景：** 用户授权设计和实现 RAG 所需资产与验证逻辑，要求完全虚构资料、保留 metadata、拒绝无充分正文证据的生产处置结论。
- **决策：** 提供 5 份原创虚构文档及 11 个离线标注场景，覆盖直接支持、仅主题相近、无资料、标题不同但正文支持、新旧/未来版本及部分覆盖。受控文档目录保存版本有效期和片段出处，不使用版本号字符串或相似度判断有效性，不重写检索或向量库。
- **语义边界：** Python 校验器负责结构、来源、正文一致性、版本、引用和要点覆盖；自然语言直接支持关系来自绑定问题的显式审查。本轮用人工编写的测试标注，不能宣称代码自动理解任意问题或识别所有语义冲突。
- **输出：** insufficient evidence 必须 abstain、明确原因并请求人工确认；不允许预训练知识兜底。supported 仅表示经审查证据通过机械校验，返回出处和原文，不生成处置结论。所有结果保留 Human-in-the-loop。
- **后续接入：** 继续遵守 DIFY_INTEGRATION.md；固定 Workflow 显式分支，abstain 不进入补充生产结论节点。问题集与审查规范不可作为业务知识导入。当前未搭建 Dify、LLM、RAG 检索或异常分析 Workflow，未改动五个业务接口。
- **验证：** pytest 覆盖标注场景、版本冲突、有效期边界、失效/未来/撤回文档、metadata、错误引用、部分覆盖及系统失败；运行完整既有 API/OpenAPI 回归。

## ADR-010：MES 快照、有效规则与显式异常闭环

- **日期 / 状态：** 2026-09-28 / 已接受（任务包 06）
- **背景：** 既有五个接口没有当前阶段及有效目标，无法据此可靠判断工艺异常。用户明确授权异常分析闭环和现有 Dify 实例联调。
- **决策：** 增加一个 MES 只读 analysis-context 接口，在同一事务返回阶段、实测值和按钢种/阶段/产线/状态/当前时刻匹配的唯一规则。SQLite 表属于模拟 MES；规则来自原创虚构正式标准，所有阈值及 6 小时有效期均明确标为教学假设。保留五个原接口。
- **流程：** Dify Start → 参数校验 → HTTP 炉次存在性 → HTTP 快照及规则 → Code 确定性比较 → 仅异常分支 Knowledge Retrieval → Evidence First → 六项报告。未知炉次、缺失数据、无有效规则或冲突立即停止；正常结果不检索。
- **证据：** 有限的预审查规程映射按范围/版本/规则/参数/方向匹配，完整受控正文直接支持每个异常才输出原文检查项；部分覆盖整体 abstain。当前不需要 LLM，不宣称实现通用语义判断或自由文本处置。所有输出无设备自动动作，必须人工复核。
- **验证：** 本地参考执行器与 Dify Code 节点共享纯 Python 函数；本地测试覆盖故障注入、有效期、快照变化、动态炉次、版本冲突及证据不足。复用 Dify 原生 economy 关键词检索验证流程，不新增模型、向量库或依赖；真实联调记录见 DIFY_LIVE_VALIDATION.md。

## ADR-011：Dify 1.17.1 HTTP 错误正文与执行失败边界

- **日期 / 状态：** 2026-09-28 / 已接受（本机版本联调发现）
- **背景：** 该版本 HTTP 节点启用 error_strategy 或 retry 后，非 2xx 进入失败策略；引擎的 fail-branch/default-value 会丢弃原 status_code/body。因此无法可靠区分业务 404 与路由 404，不能据错误文本猜测炉次存在性。
- **决策：** HTTP 节点不配置失败策略并关闭重试，使 4xx/5xx 原样进入 Code 分类。实际连接失败/超时会使 Workflow failed、无 End 输出；调用边界通过 `normalize_finished` 统一返回 system_error / WORKFLOW_EXECUTION_FAILED。调用 Dify 本身的网络异常也按系统失败处理，严禁作为空结果使用。
- **影响：** HTTP 正文错误保留原 API 语义。知识检索节点仍使用显式失败分支，保留已确认异常事实并拒绝建议。Dify 调试界面对 HTTP 断连显示运行失败是预期行为，不是工艺判断。升级版本后需复核此行为；不修改 Dify 源码、不将业务错误伪装为 API 200。

## ADR-012：FastAPI Mock API 的轻量容器部署

- **日期 / 状态：** 2026-09-29 / 已接受
- **背景：** 任务包 07 要求整理 PoC 部署并通过端到端测试，且不扩展 AI 功能或技术栈。
- **决策：** 以单个 FastAPI 服务构建 Docker 镜像；Compose 挂载一个命名卷保存 MES/ERP/WMS 模拟后端 SQLite 文件，并提供只读 `/health` 检查。Dify 保持现有独立实例，由宿主机网关访问 API；Compose 测试 profile 使用独立测试镜像执行 HTTP 端到端用例。
- **边界：** 不在 Compose 中复制或重建 Dify，不接入 LLM/RAG 服务。RAG 场景只验证仓库现有预审查 Evidence First 门禁资产；检索内容使用虚构固定夹具，不宣称验证实时 Dify 检索或开放式问答生成。
- **影响：** `docker compose up --build -d` 可运行 API；健康状态只代表三套模拟数据库可读。演示数据不会覆盖已有卷，虚构规则和测量时间仍受既有有效期约束。

## ADR-013：受控来源身份、结构化版本及正式 Qwen 索引

- **日期 / 状态：** 2026-09-30 / 已接受，阶段 A（F-001、F-004、F-011）。替代 ADR-010 中仅正文匹配与 economy 联调的旧实现。
- **来源绑定：** Dify 原生命中必须匹配受控登记中的 dataset/document/segment ID、实际文件名、version、effective_date、status、scope、钢种/阶段/规则及完整正文 SHA-256；缺失或不一致停止。Citation 仅复制通过验证的 hit，不从登记表补造；预审查检查项仍须是命中正文原句。page 可明确为 null，不补造页码。
- **版本控制：** 使用 Dify 1.17.1 官方 metadata API 存储结构化字段，Knowledge Retrieval 使用 manual AND filter（active、适用范围、开始/截止时间及必要字段）。检索前、后调用知识库文档列表，核对完整目录与当前版本唯一性；分页未取全、版本缺失、未知当前来源或冲突均 fail closed，防止 top-k 隐藏冲突。不让 Prompt 或 LLM 决定版本。
- **字段：** 内建 document_name 保存真实文件名；controlled_document_name 保存受控标题。document_id、version、status、scope、chapter、section、source_key、content_sha256、steel_grade、process_stage、rule_id、parameters、directions 为 string；effective_date/effective_from/effective_until 为 time（epoch）；page 为可空 number。segment_id 取原生 retrieval metadata，与受控登记校验。
- **迁移：** 新建正式专用 high_quality 数据集，Qwen3-Embedding-0.6B / Local Ollama / 1024 维重新索引，原旗舰 App ID 保持不变；旧 economy 与审计 clone 留作历史记录，不混用向量。
- **连接与凭证：** 目录请求使用 Dify Compose 内部 http://nginx/v1；KNOWLEDGE_API_KEY 使用只授权正式数据集的服务密钥，保存在 Dify secret 环境变量及本机忽略文件，DSL 导出留空。该地址用于现有自部署网络，其他环境需按部署调整。MES 验证使用独立 fde-stage-a Mock 卷、18088 端口，不覆盖已有记录。
- **边界：** 仍是有限预审查 Workflow，无 LLM 综合、Agent、设备执行。受控登记是规则来源登记，不是生产事实数据库；管理者更新规程后须同步来源登记、重新验证并重新发布。不声称防护可同时篡改登记与 Workflow 的管理员。
- **证据：** audit_artifacts/stage_a_dify_results.json、stage_a_document_metadata.json、stage_a_dataset.json、stage_a_embedding.json、citation_provenance_probe.json 与阶段 A pytest/Compose 报告。

## ADR-014：证据门禁之后的 DeepSeek 受约束生成

- **日期 / 状态：** 2026-09-30 / 已接受，Stage B；扩展 ADR-013 的无 LLM 边界，不改写其来源/版本/Qwen 核心实现。
- **决策：** 原正式旗舰在 evidence 通过后使用 deepseek-flash 整理事实与检查项；生产 thinking=false、原生 structured_output + json_object、reasoning separated。LLM 失败显式停止；没有成功 End 的运行继续按 ADR-011 归类系统失败。
- **契约：** 使用 stdlib 实现项目闭合 JSON Schema 子集校验、完整 JSON 解析和 native/text 一致性检查；不做括号截取或 JSON 修补。每次请求 sys.workflow_run_id 强制绑定 citation/claim/check ID；来源字段、全文 hash 与本次 verified retrieval hits 完全一致。
- **正文支持边界：** 只允许原事实句/预审查检查句全部保留并重排，逐字校验正文及引用覆盖；不是通用自然语言 entailment。最终 citation 从真实 hit 目录复制，LLM 没有造引用权限；人工提醒原样保留，无自动设备动作。
- **影响：** 保留原六项报告，成功附加 generation 对象；schema/provider/截断错误为系统失败，引用与正文越权为 abstain。失败清空生成、引用和建议，可以保留此前确认的事实。
- **验证：** 62 项新测试；全量 334 passed / 11 skipped；Compose 11；Dify 草稿 32、发布 API 4。源码和旧验收十二项冻结 SHA-256 不变。详见 GENERATION_CONTRACT.md与 audit_artifacts/STAGE_B_VALIDATION.md。

## ADR-015：只读跨系统关联与独立 API evidence

- **日期 / 状态：** 2026-10-01 / 已接受，Stage C。
- **决策：** 新增 MES 正式关联、ERP 生产订单及 WMS 批次三个最小 API；SQLite 分别属于模拟系统。Workflow 按 MES 实际关联查询并校验订单/炉次/钢种/物料/批次、单位、最低 revision 与本次请求身份，禁止模型猜测关系。
- **事实与来源：** Enterprise Evidence Bundle 保存经过校验的业务事实及独立 API provenance；生成前后从原始 HTTP 输出重建比对，不把 API 转成文档 citation。SHA-256 用于完整性，不宣称身份签名。Stage A/B 来源校验、正式 Qwen 索引与生成核心不修改。
- **生成：** 最外层包裹冻结 MES generation schema 与四条逐字校验的 API 事实句。DeepSeek 只能组织该输入；Code 持有最终来源和合成结果。身份冲突、缺证据、API/Provider 失败或生成越权停止，已取得的结构化事实可返回；原生 HTTP timeout 无 End 时继续 ADR-011 系统失败边界。
- **教学假设：** 暂复用当前 MES 规则 max_age_seconds 检查跨系统更新时间；真实接入应使用各源正式有效性/as-of 契约。所有样例虚构，业务 API 只读，automatic_actions 为空，人工决策不自动执行。
- **验证：** 详细实际命令、场景、失败中间记录与发布版本身份见 audit_artifacts/STAGE_C_VALIDATION.md；不扩展 Agent、多轮或开放式问答。

## ADR-016：独立只读 Agent 与请求级确定性门禁

- **日期 / 状态：** 2026-10-01 / 已接受，Stage D；扩展动态查询入口，不替换 ADR-015 的固定异常流程。
- **决策：** 使用实际 Dify 1.17.1 官方 Function Calling strategy 和现有 deepseek-flash；仅暴露四个 Swagger GET 工具。模型决定调用，兼容适配层控制显式对象、工具子集、MES/ERP 返回的关联键、最低版本、单位、数据时效与每请求预算。
